# Dashboard

The overview page ("Dashboard 2.0"): headline numbers, graphs and a needs-attention strip, all following one date filter, with the boxes drag-arrangeable per person. The phone-width dashboard keeps its own shape (module tiles, week strip, month grid) and is untouched by the desktop redesign.

| Feature | Status | Description | Code |
|---|---|---|---|
| One reduced dashboard call | shipped | Every card and graph is served by `dashboard_rollup` (migration 0162) in a single database round trip, with every clock edge (today, the window, the comparison window, the touch cutoffs) computed once in TypeScript and passed as parameters — the SQL and its tested TS mirror can never disagree about what day it is. Until the migration is run the page falls back to the same buckets computed from targeted queries (slower, identical numbers). The old page's ~72k-row open-lead scan per load is gone. See `docs/DECISIONS.md` #045. | `supabase/migrations/0162_dashboard_rollup.sql`, `src/lib/data/dashboard-rollup.ts` (+ `.test.ts`), `src/lib/actions/dashboard.ts` |
| Date filter over the whole page | shipped | This month (default) / Last 30 days / This quarter / Last 12 months, plus a custom from–to range — the same `DateRangeFilter` every report uses. Every KPI and period-scoped panel recomputes for the chosen window; deltas compare against the previous period (month-to-date compares to the same span of last month — `prevWindow`, pinned in `date-range.test.ts`). | `src/app/(app)/dashboard-view.tsx`, `src/lib/data/date-range.ts` |
| Needs-attention strip | shipped | Always-live cards regardless of the date filter: overdue tasks, overdue payments (phase math identical to the Payments page), contracts awaiting signature, replies waiting (the sidebar badge's own live count), appointments today. Each card opens the page that itemizes its number — Overdue Tasks opens `/tasks`, whose Overdue section counts the same rows as the card. | `src/app/(app)/dashboard-view.tsx`, `src/app/(app)/tasks/` |
| KPI row with change vs. last period | shipped | New leads, appointments, contracts signed $ (with 12-month sparkline), cash collected $ (sparkline), win rate (signed contracts out of the window's leads). Every card clicks through. | `src/app/(app)/dashboard-view.tsx`, `src/components/charts/sparkline.tsx` |
| Sales vs. cash collected graph | shipped | 12 months of signed-contract dollars (bars) against collected payments (line) on one axis, with per-month hover/focus tooltips and a screen-reader table twin. A sale is a signed true contract — change orders excluded, the Marketing Analytics rule; collected is succeeded portal payments, manual and Stripe alike. | `src/components/charts/monthly-money.tsx`, `src/lib/charts/scale.ts` (+ `.test.ts`) |
| Funnel, stages, sources, aging, team, calls, production panels | shipped | Sales funnel (the window's cohort: leads → appointment → estimate → signed, with step conversion); pipeline value by stage with a "worked in last 30/60/90 days / all" dropdown (DECISIONS #046); leads by source with signed-dollar credit; money-to-collect aging (not-yet-due / 1–30 / 31–60 / 60+ days late); team table linking to each rep's report on the same window; call activity with a 14-day dial strip; production counts. Money panels (sales-vs-cash, aging, cash KPI, overdue card) render only for `canViewFinancials` — the Payments gate. | `src/app/(app)/dashboard-view.tsx`, `src/components/charts/hbar-rows.tsx` |
| Drag-to-arrange boxes | shipped | Every panel below the KPI row drags by its header to a new spot; the order saves to `profiles.dashboard_panel_order` (own row only, same pattern as the estimates funnel cards / DECISIONS #010) with this browser's localStorage as the fallback and pre-migration path. Orders survive releases: new panels appear at their shipped spot, removed ones vanish quietly (`mergePanelOrder`, pinned by tests). | `src/lib/data/dashboard-layout.ts` (+ `.test.ts`), `src/app/(app)/dashboard-order-prefs.ts`, `src/lib/actions/dashboard.ts` (`saveDashboardPanelOrder`) |
