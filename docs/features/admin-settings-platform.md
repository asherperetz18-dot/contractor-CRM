# Admin, Settings & Platform

Auth/onboarding, the customer portal shell, platform-level administration, and the company-level settings grid (roles, company profile, checklists, scope library, certificates, project/pipeline config, webhooks, cloud storage, devices, backup, AI feature toggles, team activity, vendors).

| Feature | Status | Description | Code |
|---|---|---|---|
| Login / register / password reset | shipped | Standard Supabase-auth email/password flows; registration is invite-token gated (`loadUsableInvite`), reset/forgot-password use Supabase's token-hash flow. Password rule (min 8 chars, match check) centralized in one module so the reset-link and paid-signup-link forms can never disagree on it. | `src/app/login/`, `src/app/register/`, `src/app/forgot-password/`, `src/app/reset-password/`, `src/lib/auth/password.ts` |
| Get started / signup checkout | shipped | Public pricing/checkout entry point; whether signup is even open is read from environment config, forced to render dynamically so the page and the checkout action can never disagree (a stale static build offering a checkout the server would refuse, or vice versa). | `src/app/get-started/`, `src/lib/signup/provision.ts` |
| Post-checkout welcome/provisioning | shipped | Where Stripe returns the customer after payment; provisions the company here as well as from the webhook per Stripe's own guidance, since webhooks can be delayed — whichever path gets there first wins. | `src/app/welcome/`, `src/lib/signup/provision.ts`, `src/lib/signup/invites.ts` |
| Landing/redirect routing | shipped | Where a session lands after login — first visible nav item for the signed-in role, rather than a fixed `/` that used to bounce roles with a hidden Dashboard. | `src/lib/landing.ts`, `src/lib/nav.ts` |
| Customer portal (shell) | shipped | Separate authenticated surface for customers (not staff): magic-link login with a street-number passcode challenge as a second factor (links are long-lived enough that most arrive after the recipient has forgotten them), single-use tokens, and office-revocable access independent of the link itself. | `src/app/portal/`, `src/lib/portal/session.ts` |
| Platform admin | shipped | Separate gate and nav placement from company Settings — answers "does this identity operate the platform itself" rather than "is this an admin of the company I'm currently in". | `src/app/(app)/platform-admin/`, `src/components/platform-admin-gate.tsx`, `src/lib/data/platform-admin.ts` |
| Tutorials / help library | shipped | Narrated walkthroughs built from a demo company's real screens; deliberately excluded from the role-visibility matrix since help should be reachable by everyone, including whoever the visibility settings are currently hiding a page from. | `src/app/(app)/tutorials/` |
| Users & roles | shipped | Company member list/role assignment; includes a "reassign work" flow for moving a departing user's assigned leads/jobs to someone else (or archiving/orphaning them) before removal. | `src/app/(app)/settings/users-roles/`, `src/lib/actions/reassign-work.ts` |
| Company profile | shipped | Company-wide identity fields (name, address, license number, tax ID, contact info) used across documents, portal, and communications. Tax ID is free text on purpose — EIN, SSN, and state formats all vary. | `src/app/(app)/settings/company-profile/` |
| Role visibility | shipped | Per-role, per-page visibility matrix controlling which nav pages a role can see at all (separate from the RLS permission checks that control what data a role can act on). | `src/app/(app)/settings/role-visibility/` |
| Menu order | shipped | Per-user custom ordering of the nav menu. | `src/app/(app)/settings/menu-order/` |
| Checklist templates | shipped | Company-defined reusable checklist templates applied to projects (see also Projects domain). | `src/app/(app)/settings/checklist-templates/`, `src/lib/actions/checklists.ts` |
| Scope library | shipped | Reusable scope-of-work templates, filterable by project type, for building estimates faster. | `src/app/(app)/settings/scope-library/`, `src/lib/actions/scope-templates.ts` |
| Certificates (licence & insurance) | shipped | Company license/insurance certificates surfaced on the customer portal, replacing texting them one at a time on request. | `src/app/(app)/settings/certificates/` |
| Project types | shipped | Company-editable list of project type values with duplicate-value merging, used across leads/estimates/reporting. | `src/app/(app)/settings/project-types/` |
| Pipeline stages | shipped | Company-editable, ordered list of pipeline stage names; referenced by name (not a fixed enum) by the estimate-driven auto-advance logic elsewhere in the app. | `src/app/(app)/settings/pipeline-stages/` |
| Incoming webhooks | shipped | Per-company webhook secret (regeneratable) used to authenticate the external leads webhook. | `src/app/(app)/settings/incoming-webhooks/` |
| Cloud storage (Google Drive) | shipped | Per-company Google Drive connection status and sync stats (files synced vs. total, by category) for document backup/storage. | `src/app/(app)/settings/cloud-storage/`, `src/app/api/oauth/google-drive/`, `src/lib/actions/google-drive.ts` |
| Signed-in devices | shipped | Lists where each team member is currently signed in and lets an admin cut a specific device/session off. | `src/app/(app)/settings/devices/` |
| Backup | shipped | Shows record counts a full backup would contain (without shipping every row to the browser) and triggers the actual export; a nightly cron also runs it automatically. | `src/app/(app)/settings/backup/`, `src/lib/backup.ts`, `src/app/api/cron/backup/` |
| AI analysis settings | shipped | Per-company toggle + model choice + custom positive/negative signal prompts for the lead-conversation AI analysis feature, and a separate toggle for AI call notes. | `src/app/(app)/settings/ai-analysis/` |
| AI activity log | shipped | Audit log of AI-proposed actions (`ai_action_proposals`) for admin review. | `src/app/(app)/settings/ai-activity/` |
| AI estimator settings | shipped | Per-company configuration for the AI scope-to-line-items estimator feature. | `src/app/(app)/settings/ai-estimator/` |
| Team activity | shipped | Admin-only audit trail of team actions, opens scoped to just today's events by default — a prior version pulled 90 days (26,705 rows / 3.4MB) across twenty sequential round trips on every visit regardless of what the viewer actually looked at. | `src/app/(app)/settings/team-activity/`, `src/lib/actions/activity-range.ts` |
| Vendors | shipped | Vendor list backing Bills to Pay; access is by a specific `canEditVendors` check rather than the broader cost-management permission, since Field can record receipts under a vendor without being allowed to edit the vendor list itself. | `src/app/(app)/settings/vendors/`, `src/lib/actions/vendors.ts` |
| Version endpoint | shipped | Public endpoint reporting the deployed build/version, used for deploy verification. | `src/app/api/version/` |
| Activity ping | shipped | Lightweight endpoint used to record a user is actively online (backs "signed-in devices" / presence). | `src/app/api/activity/ping/` |
