# Estimates, Contracts & Projects

The document lifecycle (estimate → signed contract → change orders → completion) and the production/project tracking that follows a signed job.

| Feature | Status | Description | Code |
|---|---|---|---|
| Estimate builder | shipped | Line-item estimate editor (qty/unit/price, margin, discount) with scope sections, locking once signed, and a "recall" flow for post-signature edits. Access-gated with an explicit "you don't have access" message rather than a silent empty list, so missing permissions don't read as missing data. | `src/app/(app)/estimates/`, `estimate-builder.tsx`, `scope-editor.tsx`, `sections-bar.tsx` |
| Optional line items | shipped | A line marked Optional shows priced on the customer's document with a tick box; it joins the subtotal, tax and deposit only when the customer ticks it in the portal (totals re-derived server-side). An office save clears earlier ticks — same reasoning as the recall flow — and the PDF spells the state out in words. | `estimate-builder.tsx`, `src/components/optional-item-checkbox.tsx`, `src/lib/actions/portal-estimates.ts` (`setOptionalItemAsCustomer`), `supabase/migrations/0142_optional_line_items.sql` |
| AI scope-to-line-items | shipped | Claude proposes priced line items from a scope description; nothing reaches the actual estimate until a human explicitly accepts each line — by design, so "the AI suggested it" is never the justification for a price on a document a homeowner signs. | `generate-lines-modal.tsx`, `src/lib/actions/scope-ai.ts` |
| Portal e-signature | shipped | Customer-facing signing flow (outside this domain's UI, see `src/lib/portal/`) with signature evidence capture and a rep notification once a document is fully signed. | `src/lib/estimate-signing.ts`, `src/lib/portal/signature-evidence.ts`, `src/lib/portal/rep-signed-notification.ts` |

Paper signatures and pre-capture rows show no line rather than fabricated precision; times are labelled UTC because the server can't know the signer's timezone. | `src/lib/portal/signature-evidence.ts` (`signatureEvidenceLine`), `src/components/estimate-document.tsx`, `src/lib/pdf/document-pdf.ts`, `src/lib/actions/estimates.ts` (send) |

| Change orders | shipped | Change orders against a signed contract only — the estimate itself stays editable pre-signature, so a change order can't be raised against a document the customer hasn't agreed to yet. | `change-orders.tsx`, `src/lib/actions/change-orders.ts` |
| Pending change orders card | shipped | A "Change Orders · pending" card on the Estimates funnel: change orders still unsigned and alive (Draft/Sent/Viewed, expiry respected), totalling the money still waiting for a signature.
